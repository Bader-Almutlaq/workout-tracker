# Workout Tracker

Personal iPhone workout tracker replacing Strong. **Read `.claude/PLAN.md` first** and keep its Status section current. The other key docs are `docs/ARCHITECTURE.md` (code structure), `docs/DATA.md` (storage, backups, import format), `docs/DESIGN.md` (visual system and charts) and `docs/DECISIONS.md` (why things are the way they are).

The owner does not read Swift. Code must therefore explain itself to the next agent through structure, names, doc comments and tests.

## Product rules

- The owner is an advanced lifter who knows the literature. The app **measures and calculates; it never prescribes** a training style. Progression logic is opt-in and user-defined.
- No AI features, exercise videos, social, streaks or celebrations. Keep the UI uncluttered.
- Every analytics formula cites its source from `reports/Workout tracker app research.md` in its doc comment, or is marked `Heuristic:` with the reason.
- **Data safety first.** Never ship a migration, importer or restore path that can lose data without taking a snapshot first. Weights are stored in kilograms, exactly as entered; display conversion happens only in the UI layer.

## Engineering rules

**One concept, one implementation, one place.**
- Each concept (e1RM, fractional sets, unit conversion, outlier check, backup…) has exactly one implementation in `WorkoutCore`. Views and other code call it; they never re-derive it.
- One primary type per file, with the file named after the type.
- Before writing a helper, search for an existing one.

**Layers** (see `docs/ARCHITECTURE.md`):
- `Packages/WorkoutCore`: models, database, import, analytics, backup. No SwiftUI, no UIKit. Everything testable with `swift test` on the Mac.
- `App/`: SwiftUI only. Views hold no business logic: they render state from an `@Observable` model and forward user intent to it.
- Dependencies point inward only: App → WorkoutCore, never the reverse.

**Swift style.**
- Swift 6 language mode with strict concurrency. Use value types (`struct`, `enum`) by default. Use `actor` or `@MainActor` for shared mutable state; never `@unchecked Sendable` without a comment explaining why it is safe.
- No force unwraps (`!`), `try!` or `fatalError` outside tests, except for programmer errors that are provably impossible, with a comment saying why.
- Errors are typed `enum`s conforming to `Error` and `LocalizedError` with a user-readable message. Never swallow errors silently: log them and surface them.
- Logging uses `os.Logger` with subsystem `com.ketchup.workouttracker` and one category per module (`database`, `backup`, `import`, `analytics`, `ui`). No `print`.
- Names are full words (`estimatedOneRepMax`, not `e1rm`) except well-known domain abbreviations defined in `docs/ARCHITECTURE.md` (RIR, RPE, e1RM).
- No magic numbers. Constants live in a named `enum` namespace with a doc comment and a citation.
- No dead code, commented-out code, speculative protocols or abstractions with a single implementation "for later".

**Documentation.**
- Every public type, function and property gets a `///` doc comment: what it is, its units, and edge cases. Formulas include the equation and the citation.
- Comments explain *why*, not what. No narration such as "// loop over sets".
- When a non-obvious choice is made, add a short entry to `docs/DECISIONS.md`.

**Tests.**
- Swift Testing (`import Testing`, `@Test`, `#expect`). Every `WorkoutCore` feature ships with tests: happy path, edge cases, and a regression test for every bug fixed.
- Formulas are tested against the worked examples in the research report.
- The importer is tested against small synthetic fixtures in `Tests/…/Fixtures/`, never against the owner's real export (that stays in `export_data/`, which git ignores).

**Database.**
- Migrations are append-only. Never edit a migration that has shipped to the phone; add a new one.
- The app takes a local snapshot automatically before running pending migrations.

**Workflow.**
- Common commands live in the `Makefile` (`make help`). Use them rather than ad-hoc commands, so every agent builds the same way.
- Before calling work done: `make test` passes, `make build` passes, and PLAN.md Status is updated.
- Keep commits small, one concept each, with imperative messages ("Add Strong CSV parser"). Commit only when the owner asks.

## Environment

- Xcode 27.1 at `/Applications/Xcode.app` (license accepted). The Makefile sets `DEVELOPER_DIR` itself, so it works even if `xcode-select` points at CommandLineTools.
- The Xcode project is generated by XcodeGen from `project.yml`. Edit `project.yml`, never the `.xcodeproj` (it is git-ignored and regenerated by `make project`).
- Signing uses a free Apple ID (Personal Team). The team ID goes in `Config/Local.xcconfig` (git-ignored). Keep bundle ID `com.ketchup.workouttracker` fixed forever: changing it orphans the data on the phone.
- The shell has the RTK command rewriter. If a command misbehaves, prefix it with `rtk proxy`.
